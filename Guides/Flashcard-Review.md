# 知识卡片与明确反馈

卡片让人先回想，再对照解释。每张围绕一个概念的用途、机制、边界或应用；能解释关键关系的公式和推导值得保留。题目应脱离原聊天也能读懂，简答先定义必要符号，展开再补细节。

卡片保存在 Flashcards，来源来自正式知识目录。待学页完成相应学习后再接入 Concepts。新卡第一次进入题组不代表用户第一次见到这个知识，也不代表已经掌握。

## 一轮复习

1. 读取知识入口、近期修改和明确纠错。运行 `python3 .flashcards/review.py audit` 与 `python3 .flashcards/review.py scan`。
2. 核查变化来源，再按实际价值补充卡片。完成处理的资料才用 `ack-sources` 确认；未读部分继续保留。
3. 运行 `python3 .flashcards/review.py session`。工具返回当天界面路径，默认保存在 .flashcards/local/views/。可在浏览器打开；宿主支持 HTML 可视化时，可用 `--fragment --output <文件>` 生成嵌入版本。
4. 用户先回想、翻看解释，再提交评分或文字意见。普通浏览器导出 JSON，交给 Codex 或通过 `feedback --input <文件>` 保存。有聊天宿主接口时可从界面发起保存请求。
5. 以工具返回的 saved、duplicates 和 historical_only 确认保存结果。导出文件或发出消息尚未改变数据库中的复习安排。

默认每天最多 10 张，首次推送最多 6 张，同一概念最多 2 张。其余名额用于复习，新卡不足时仍可生成纯复习题组。没有可用或到期卡时明确提示，不写入空快照。漏跑后从当天继续，同日重跑复用原快照。

“没想起来”“有点模糊”“比较熟悉”分别在收到评分后的 1、3、14 天重新进入候选。到期后优先安排，再按推送时间及主题轮换。每日上限可能延后实际出现时间。它们是可配置的固定间隔，尚未实现 FSRS，也没有据此验证学习效果。没有明确反馈时只轮换内容，个人掌握程度保持未知。

## 内容与版本

每个卡片文件用 `type: flashcard_set`。每张卡以二级标题分隔，隐藏 JSON 记录 id、version、status、concept、topic、sources；正文依次使用三级标题“正面”“简答”“展开”“来源”。完整示例见示例库 Flashcards 目录；空白学习目录可按此约定让 Codex 制卡。

ID 使用 `sb-fc-0001` 形式并保持稳定。status 为 active、paused 或 retired。每个来源有仓库相对 path、精确 heading 与该章节的 sha256。

先读完来源并确认它支持卡片，再运行：

```sh
python3 .flashcards/review.py source-hash 'Concepts/数理基础/标准误.md' '定义与条件'
```

来源变化、消失或标题不唯一时，卡片退出新题组。核查后更新文字、来源指纹和版本。指纹只能发现文本变化，不能核验科学正确性或远程原文是否更新。卡片正文或来源改变却未升版本时，工具拒绝注册新内容。

旧题组保留原内容和版本；查看旧题组时说明当前来源变化。旧版反馈只保留到历史，不直接调整新版间隔。退役卡保留历史。修订预览不生成新题组，也不接受评分。

## 反馈与保存

反馈必须绑定原题组的 workspace_id、session_date、card_id 和 version；按原 position 核对自然语言反馈。工具按 batch_id 去重，整批有非法编号或版本时回滚。不同学习目录的反馈不能混用。

翻面、关闭和草稿都不算提交。普通浏览器的草稿尽力保存在本机；数据库才是已导入反馈的记录。文字疑问单独保存，不自动转换为熟悉度。纠错先核查来源；同类问题可据实际反馈改进指南与其他卡片。

.flashcards/local/review.sqlite3 保存版本、快照、反馈与来源处理位置，属于需要备份的个人数据。生成界面可以重建。复制模板时不带出此目录；迁移自己的真实记录时应整体备份数据库，而非新建一份记录后混合导入。
