# 定期整理，也可以交给 AI

[English](Automation.md)

在我自己的日常工作流里，我在 Codex 中配置了定时任务，定期读取选定的学习对话并更新概念、主题地图和候选待学页。核心的本地文件整理与浏览器每日卡片同样适配任意能读写本地库、运行命令并接入定时的助手；至于「定时自动读取聊天历史」，则取决于你使用的客户端本身是否开放对话历史接口。

## 每日知识卡

浏览器卡片是每个知识库通用且固定的私人网址（`Today.command` / `Today.cmd`）。在存放知识库的电脑上打开一次「今日知识卡」并加入书签，之后随时可以翻卡、评分和留言；点**保存**后会立即写回本地并计入排期。文字留言在「我的留言与回复」里显示进度，等待助手下一次准备题组时处理（也可以直接叫它现在跑一轮）。

选任何能读写本地文件并执行命令的 AI 助手（或借助系统定时器触发），把下面这段设为每日任务，并在配置完成后试跑一轮，固定书签就会切到助手发布的题组：

> 在这个知识库里按 Prompts/每日复习.md 工作。先找出还没处理的留言，逐条答复、修卡或补卡，把结果留给我。再看最近学过的内容，更新复习卡，有合适的新概念就做一张待学卡。把今天的卡发到我的私人网址。

新一轮发布前，书签仍可打开上一期；如果端口被本机其他程序占用，入口会提示稍后重试，原地址继续有效。助手可随时用 `today --no-open` 取回地址。若只想自己随看随选已有卡，用 `daily --on-demand` 即可恢复打开时现抽。跨时区可在 `.secondbrain.json` 指定 `timezone`。

浏览器页面适用于所有客户端；如果所用宿主还支持在聊天窗内直接嵌入交互卡片（例如 Codex 桌面客户端），发布时加上 `--chat-output <路径>` 就能在聊天里同步收到同一组卡，两端的保存操作写入同一份数据库记录。[卡片格式](Flashcard-Review.md#新概念卡)

## 先确认你的环境能做什么

作者个人的桌面环境向助手提供了会话列表和历史读取接口，因此能在授权范围内增量整理选定的 Codex 与 ChatGPT 对话；这项能力来自宿主应用，本仓库没有内置聊天抓取器，也不假设所有客户端都具备相同接口。

先让你的助手做一次小范围核实：

> 请只检查我选定的一段学习对话：你能读取哪些消息和附件，能否继续读取前文，能否写入当前知识库？先说明实际覆盖范围，再建议怎样定期整理。

| 当前能力 | 可以怎样安排 |
| --- | --- |
| 能读授权的对话历史，也能写本地文件 | 用宿主客户端的定时任务，增量整理选定对话里学过的部分 |
| 只有本地文件访问 | 定期处理放进库内指定目录的聊天导出或手动保存片段 |
| 只有网页或手机端聊天 | 先生成纯文本/Markdown 稿件自行存库；直写本地需接文件能力 |
| 有定时能力，缺少历史读取接口 | 定期回顾既有笔记卡片，或整理你主动放进目录的已学材料 |

涉及本地目录的桌面定时任务通常需要电脑开机且应用有目录权限；以 Codex 为例，不同触发环境可用工具有所区别，设置前可参考[官方说明](https://developers.openai.com/codex/app/automations/)。若客户端不开放历史接口，也可以定期导出聊天（如 ChatGPT 的[数据导出](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)）后交由本地任务增量读取。

## 一份可以调整的整理提示

先手动跑通一次再设频率（例如每几天一次），依材料体量和费用微调：

> 从上次读到的位置继续，按 Prompts/整理材料.md 整理我在选定对话或导出文件里已经学过的部分。以我的追问、练习、复述或明确说明判断范围，保留出处和手写内容。用 Prompts/回顾与补学.md 找能连起几个已有节点的新概念。写入指定的知识库，检查链接和卡片来源，把原文缓存、读取范围和待核实的部分记在 .local/。

配置时明确写清允许访问的对话/导出目录、目标知识库、运行间隔和上限。任务必须读实际消息而不是仅靠标题摘要，处理指针可记在 `.local/maintenance.md` 方便续跑。跑完几轮后随手抽查一页更新过的概念和候选待学页，看每条连线是否言之有物。

## 公开仓库的维护实践

如果你维护自己公开发布的模板仓库，务必把公开仓巡检（看 issue、核对文档与脚本一致、临时目录试跑）与私人学习库彻底隔离，涉及兼容、许可、文风或核心设计由本人拍板。下载本模板不会自行安装后台任务、读取其他目录或对外发送任何内容。
