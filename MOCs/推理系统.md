# 模型从接到请求到答完，时间花在哪里？

读输入和往外生成是两段不同的工作。沿一条请求看，可以分清用户在等什么。几条请求同时到来时，还要考虑调度和显存怎样影响等待。

**等第一个 token。** [Prefill 与 Decode](../Concepts/推理系统/Prefill%20and%20Decode.md) 用 a、b、c 说明，模型在读完提示词时已经能选出第一个输出。资料问答会把选中的段落也放进这次输入。[检索与生成](检索与生成.md)从另一个方向讲这些段落是怎么选出来的。

**等接下来的 token。** 每一步都要用到前文。[KV 缓存](../Concepts/推理系统/KV%20Cache.md)留下各层的键和值，[PagedAttention](../Concepts/推理系统/PagedAttention.md)给不断增长的缓存按块分配空间。几条请求长短不一时，[连续合批](../Concepts/推理系统/Continuous%20Batching.md)让短请求腾出位置，长请求继续。

**什么改动能缩短等待？** [分块预填充](../Concepts/推理系统/Chunked%20Prefill.md)把长输入分几轮处理，[前缀缓存](../Concepts/推理系统/Prefix%20Caching.md)则复用已经算过的共同开头。比较效果时，可以让两种配置服务同一批请求，用[配对评测](../Concepts/研究方法/Paired%20Evaluation.md)区分哪些请求变快了，再看[首 token 延迟和吞吐](../Concepts/推理系统/Inference%20Latency%20and%20Throughput.md)各自怎样变化。
