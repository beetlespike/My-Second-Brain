# 准备今日知识卡

[English](daily-review.md)

在用户授权的知识库里运行下面的命令，把整套制卡与修卡包圆，让用户只需丢链接、收藏一个固定私人网页书签即可复习与提问。用户的评分、留言和你的答复都留在同一个库。

1. **先读留言。** 运行 `python3 .flashcards/review.py daily`。当 `status` 为 `feedback_pending` 时，按 `items` 的顺序从最早的留言读起。每条记录标明所属期次（`session_date`）、卡片编号和版本，并附上可查到的原题、答案和出处。`pending_count` 是待处理总数，每页最多 20 条。有 `next_after` 时，将它的值传给 `daily --after <编号>` 读取下一页。
2. **处理到具体结果。** 对照当时的卡、当前版本和原文章节。能直接解释就回答，回复中的行内公式可写作 `$...$`，单独成行的公式可写作 `$$...$$`。题目含糊就改清楚，答案有误就订正。适合单独练的问题可以另做一张。复习卡保留原 ID，修改题面、简答、展开、概念、主题或来源后递增 `version` 并核对来源。只改术语释义或作者 `author` 时沿用原版本。待学卡直接改待学页（`待学概念/` 或 `Study-Queue/`）里的卡片小节。把留言当作读者对这张卡的反馈。还缺依据的留言保留待处理，先处理其余留言。
3. **把结果交还给读者。** 用 `python3 .flashcards/review.py resolve --input -` 从标准输入提交 UTF-8 JSON，沿用 `daily` 返回的 `workspace_id` 和留言 `id`。例如：

```json
{"workspace_id":"<本库 ID>","items":[{"id":12,"outcome":"revised","version":3,"reply":"题目补上了链路带宽，卡背也列出了两阶段拆分前后的延迟。"}]}
```

   每种处理结果都要在 `reply` 里给读者实际答复。`answered` 填好答复即可。`revised` 要给出原复习卡修订后的 `version`，如是待学卡，工具会核对笔记里的题目或简答是否已修改。`linked` 要给出另一张已核验复习卡的 `card_id`、`version`，并在答复里解释两者的关系。读者可在「我的留言与回复」看到结果。
4. **做卡、更新、发布。** 回到 `daily` 确认 `ready_to_prepare`。用 `scan` 读新材料或变动的章节，修订受影响的卡，按需要为已学概念补题。只有核对过的材料才用 `ack-sources` 标记。前置概念较密集时，可在卡片的 `### 相关概念` 小节下写两三条 `- 术语：简短解释`，方便读者点开温习。用 `audit` 检查格式、来源与可用性。顺着联系自主发现的候选概念可以先做成待学探索卡，运行 `python3 .flashcards/review.py daily --publish`，选了待学卡就加 `--discovery <待学页路径>`。`published` 返回固定私人网页 `url`。准备期间又收到留言会返回 `feedback_pending`，处理后再发布。上一期仍可打开。

用户只想找回书签地址时，用 `python3 .flashcards/review.py today --no-open` 取回即可。网页保存后即刻入库，留言马上出现在待处理列表。配置了定时任务的库会在下一轮处理。用户也可以要求现在处理。

*(可选聊天内嵌组件：若当前桌面客户端支持内嵌交互卡并启用了 `--chat-output <宿主可显示的 HTML 路径>`，可同时展示返回的 `fragment`，并将用户在聊天提交的内容原样送入 `feedback --input -`，按 `saved`、`duplicates`、`historical_only` 确认结果；网页端和聊天端写入同一份数据库。)*
