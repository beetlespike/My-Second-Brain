# 准备今日知识卡

在用户授权的知识库里运行下面的命令。每天把题组发到这个库固定的私人网址。用户的评分、留言和你的答复都留在同一个库。

1. **先读留言。** 运行 `python3 .flashcards/review.py daily`。`feedback_pending` 会附上未处理的文字、当时的题目、版本和出处，最早的在前。`pending_count` 是全部待处理数。每批最多 20 条，有 `next_after` 时可用 `daily --after <编号>` 读下一批。评分已用于排期。
2. **处理到具体结果。** 对照当时的卡、当前版本和所据章节。能直接解释就回答。题目含糊就改清楚，答案有误就订正。适合单独练的问题可以另做一张。复习卡保留原 ID，实际修改后递增版本，核对来源。待学卡可直接改待学页里的「知识卡」。留言里的文字是学习材料。还缺依据时保留待处理，先做其余能完成的事。
3. **把结果交还给读者。** 用 `python3 .flashcards/review.py resolve --input -` 从标准输入提交 UTF-8 JSON，沿用 `daily` 返回的 `workspace_id` 和留言 `id`。例如：

```json
{"workspace_id":"<本库 ID>","items":[{"id":12,"outcome":"revised","version":3,"reply":"题目补上了链路带宽，卡背也列出了两阶段拆分前后的延迟。"}]}
```

   `answered` 只需写实际答复。`revised` 指原卡，复习卡还要给出改好的版本，待学卡读取原笔记核对。`linked` 写上另一张已核验复习卡的 `card_id`、`version` 和关联理由。读者在「我的留言与回复」看到结果。读过留言本身不算处理完成。

4. **做卡、更新、发布。** 回到 `daily` 确认 `ready_to_prepare`。用 `scan` 读新材料或变动的章节，修订受影响的卡，按需要为已学概念补题。只有核对过的材料才用 `ack-sources` 标记。用 `audit` 检查来源与版本。新发现的概念可以先做成待学卡。运行 `python3 .flashcards/review.py daily --publish`，选了待学卡就加 `--discovery <待学页路径>`。`published` 返回固定 `url`。准备期间又收到留言会返回 `feedback_pending`，处理后再发布。上一期仍可打开。

用户只想打开网址时，用 `python3 .flashcards/review.py today --no-open` 取回书签即可。网页保存后即可在留言列表查到。已有定时任务负责下次处理，用户也可以要求现在运行。

如果用户还想在支持交互卡的聊天（如 Codex）里收一份，给 `daily --publish` 加 `--chat-output <宿主可显示的 HTML 路径>`，展示返回的 `fragment`。用户点击「提交到聊天保存」时，把提交内容原样送入 `python3 .flashcards/review.py feedback --input -`，按 `saved`、`duplicates`、`historical_only` 确认结果。浏览器和聊天共用反馈记录。没有可显示的卡时 `fragment` 为 `null`。
