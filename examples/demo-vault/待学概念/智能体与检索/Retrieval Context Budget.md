# 检索上下文预算

检索上下文预算是提示词里为检索片段留出的空间，通常按 token 计。定下预算之后，再决定哪些片段进提示词。

- [检索与重排](../../Concepts/智能体与检索/Retrieval%20and%20Reranking.md)找出候选片段并给它们排序。预算决定排完之后，实际能留下多少内容。
- [Prefill 与 Decode](../../Concepts/推理系统/Prefill%20and%20Decode.md)解释模型怎样处理输入和生成输出。送进提示词的片段越长，prefill 要处理的位置就越多。
- [RAG](../../Concepts/智能体与检索/RAG.md)用传给模型的片段支持答案。用有限空间选片段时，要保留会影响结论的条件和例外。

## 一道有预算的题

假设这一请求最多容纳 4096 个 token。说明与问题占 600，另外给输出留 500，资料一共能占 2996。手上有四个候选片段，每份分别占 1500、1000、900、700 个 token。第一份给结论，第二份给实验条件，第三份与第一份重复，第四份包含一个例外。怎样选能同时保留结论、条件和例外？

1500、1000、700 加起来要 3200，超过预算 204。可以检查哪部分可从原片段中裁掉，或者重新检索更短、仍指向原文的证据。若把包含例外的片段整个丢掉，生成时容易一句话把结果说得太宽。

这组数字是合成例子。算自己的例子时，把提示模板和引用标记也计入长度。可以试着缩小预算，看看哪些证据会先被舍掉。

## 知识卡

### 正面

检索已经找到了讲例外的片段，为什么模型的回答仍可能漏掉这个例外？

### 简答

找到的片段还要经过筛选，并装进有限的输入空间。如果重复的材料占满了这个额度，讲例外的片段就进不了模型的输入。可以去重或缩短片段，给会改变答案的证据留出空间。
