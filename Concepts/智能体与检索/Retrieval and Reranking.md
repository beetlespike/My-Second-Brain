# 检索与重排

一组检索结果往往先要找得快，再要排得准。第一轮可以用关键词或预计算的向量相似度挑出少量候选。重排模型再逐个查看问题和候选片段，按相关程度重新排队。

## 为什么第一轮候选仍然重要

假设问题是“报告有没有区分首 token 延迟和整段生成时长？”检索器找出了谈吞吐的几段，也找出了定义首 token 延迟的段落。重排可以把定义段落提到第一位。如果第一轮根本漏掉定义段落，重排也无法把它补回来。

[RAG](RAG.md) 会用重排后的片段准备输入。要看重排是否确实有用，可以固定候选和题目，只更换排序办法，逐题核对支持答案的段落是否进入前几位。[配对评测](../研究方法/Paired%20Evaluation.md) · [BERT passage reranking](https://arxiv.org/abs/1901.04085)

还可以分开算候选集和最终输入的[检索召回率](../模型评测/Retrieval%20Recall.md)，看看证据漏在了哪一步。
